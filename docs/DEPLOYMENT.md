# Vercel deployment

Ledgerly is a static frontend with optional Supabase Auth/Postgres cloud features. Vercel is the intended host, but the connected Vercel account currently has no Git-linked projects in the selected team, and the management integration returns HTTP 403 when creating a project or deployment. No live URL is verified. The repository includes a guarded GitHub Actions workflow to use after a Vercel project is created with an account that has the required permissions.

## Create/link the Vercel project

1. Open the [Vercel dashboard](https://vercel.com/dashboard) using the account/team intended to own Ledgerly.
2. Import the GitHub repository webt3ch/Ledgerly and grant Vercel access to it if prompted.
3. Set the project name to ledgerly, the root directory to /, and use the default static-site detection (the app is a root-level index.html with vercel.json).
4. Finish creating the project and make sure its first deployment succeeds.
5. Copy the actual Organization ID and Project ID from Vercel project settings (or from .vercel/project.json after linking locally). Do not use IDs from another team/project.

If Vercel cannot import the repository, check that the GitHub integration is connected to the correct GitHub account and that the selected Vercel team is permitted to create projects. Do not repeatedly retry the same failed API request.

## GitHub Actions deployment

Workflow: .github/workflows/deploy-vercel.yml. It validates the source and builds/deploys production on pushes to main or manual dispatch, but only when the repository Actions variable VERCEL_DEPLOY_ENABLED equals true.

In GitHub → Settings → Secrets and variables → Actions, create these repository secrets using the values from the newly created Vercel project:

- VERCEL_TOKEN: a token generated by the account that has access to the project.
- VERCEL_ORG_ID: exact Organization ID from the Vercel project settings.
- VERCEL_PROJECT_ID: exact Project ID from the Vercel project settings.

Create Actions variables:

- VERCEL_DEPLOY_ENABLED = true (only after the project is linked and the secrets are correct).
- SUPABASE_URL = Supabase Project URL (leave empty until Supabase is configured).
- SUPABASE_ANON_KEY = public anon/publishable key (leave empty until Supabase is configured).

The workflow writes these two Supabase values into config.js immediately before building the static site. These values are browser-public and must be protected by database RLS; never substitute a service-role key. Keep the Vercel token in GitHub Secrets—never send it in chat or commit it to a file.

Run Actions → Deploy production to Vercel → Run workflow. Confirm the action succeeds, open the URL printed by the Vercel CLI and test the deployed page before calling Ledgerly published.

## Supabase public frontend configuration

The application uses a browser-safe config.js. Only the Supabase Project URL and anon/publishable key may be placed there. Database Row-Level Security is mandatory.

The values are currently blank, so cloud auth and sync are intentionally unavailable. Configure Auth redirect URLs for the verified Vercel production URL and intended preview URLs after deployment. Provider client secrets stay in Supabase Auth settings, never in GitHub or frontend code.

## Release gates

- Production URL serves the complete app and its assets with HTTPS.
- Check desktop, tablet, mobile, console errors, and network failures.
- Test email registration, email confirmation, password recovery, Google OAuth and Microsoft OAuth with real test accounts.
- Test local-to-cloud migration with backup and confirmation.
- Verify two-user authorization/RLS isolation, revision-conflict handling, export and cloud account deletion.
- Notifications must be called enabled only after a server scheduler/provider is set up and delivery is tested.

## Scope

GitHub Pages can serve only the static UI; it does not run a backend API or scheduled notification worker. Vercel is preferred because it can host the frontend and later server-side functions. A working deployment alone does not make OAuth, sync or notifications active.
